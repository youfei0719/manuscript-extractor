# 稿件提取 v0.1.19

## 更新内容

- 修复 TokenFlux 错误响应解析：同时支持 OpenAI 风格的 `error.message` 和 TokenFlux 顶层 `message`，不再把具体原因丢失为笼统的 HTTP 502。
- 502/503 会根据服务商返回的脱敏原因显示更准确的处理建议，包括上游认证失败、上游拒绝访问、可用账号耗尽、当前分组没有可用账号和上游服务过载。
- 对明确的上游认证失败和上游拒绝访问不再重复发起无效重试，减少等待时间和无意义请求。
- 保留现有错误码 `LLM_PROVIDER_UNAVAILABLE`，同时在用户提示和运行日志详情中保留可行动的根因信息。

## TokenFlux 配置说明

- OpenAI 兼容地址应使用 `https://tokenflux.dev/v1`，请求路径由应用自动补全为 `/chat/completions`。
- `gpt-5.5` 必须是当前 TokenFlux API Key 所属分组允许的完整模型 ID；若持续收到上游认证或账号耗尽提示，应在 TokenFlux 使用记录中核对分组、余额和上游账号状态。

## 安全与数据

- API Key、Cookie、更新签名私钥和完整上游响应不会提交到代码、发布资产或运行日志；错误详情经过脱敏和长度限制。
